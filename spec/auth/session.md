# Aegis Spec — Session

Status: Draft 0.1 · Normative
Key words **MUST**, **MUST NOT**, **SHOULD**, **SHOULD NOT**, **MAY** are as defined in RFC 2119 / RFC 8174 when in capitals.
Types are defined in `auth/principal.md` §0.

## 1. Definition

A **Session** is the server-side record of one authenticated login on one device/client. It is the unit of revocation, of concurrency limiting, and of device listing.

* Every authenticated Principal MUST be backed by exactly one Session (see `principal.md` §2.1.2).
* A Session exists for **every** transport, including access-token + refresh-token transports. A conforming implementation MUST NOT offer a mode in which no Session record exists, unless that mode is explicitly named as unsafe and is excluded from conformance claims.
* A Session is *not* a token. Tokens are credentials that reference a Session (`tokens.md`).

## 2. Structure

```
Session {
  id                  : Id                          REQUIRED, immutable
  userId              : Id                          REQUIRED, immutable   (subject id)
  subjectType         : SubjectType                 REQUIRED, immutable
  authMethod          : String(1..64)               REQUIRED, immutable
  amr                 : List<String(1..32)>         REQUIRED, immutable   may be empty
  authenticatedAt     : Timestamp                   REQUIRED, immutable
  createdAt           : Timestamp                   REQUIRED, immutable
  lastSeenAt          : Timestamp                   REQUIRED
  idleExpiresAt       : Timestamp                   REQUIRED
  absoluteExpiresAt   : Timestamp                   REQUIRED, immutable
  revokedAt           : Timestamp?                  set iff status = revoked
  revokedReason       : RevocationReason?           set iff status = revoked
  device              : DeviceInfo?                 OPTIONAL
  securityVersionAtIssue : Integer                  REQUIRED, immutable
}
DeviceInfo {
  label      : String(0..100)?      host-supplied display name
  userAgent  : String(0..512)?      truncated, never trusted
  ip         : String(0..45)?       as supplied by host's trusted-proxy logic
}
RevocationReason =
    "logout" | "logout_all" | "admin" | "password_changed" | "password_reset"
  | "account_state" | "credentials_invalidated" | "refresh_reuse_detected"
  | "evicted" | "expired_cleanup"
```

### 2.1 Derived status

`status(session, now)` is a pure function:

| Condition (evaluated in this order) | Status |
|---|---|
| `revokedAt` is set | `revoked` |
| `now ≥ absoluteExpiresAt` | `expired` |
| `now ≥ idleExpiresAt` | `expired` |
| otherwise | `active` |

An implementation MUST derive `expired` from timestamps at read time. It MUST NOT depend on a background job to make an expired session unusable. (Background deletion is permitted as housekeeping only.)

### 2.2 Constraints

1. `id` MUST be generated by the `IdGenerator`/`Random` port with at least 128 bits of entropy when it is also used as, or derivable into, a bearer credential (opaque-session transport, see `tokens.md` §5); otherwise it MUST at least satisfy `Id`.
2. `absoluteExpiresAt = createdAt + absoluteTtl` and MUST NOT change after creation. No operation (touch, refresh, resolve) may extend it.
3. `idleExpiresAt` MUST satisfy `createdAt < idleExpiresAt ≤ absoluteExpiresAt`. It MUST be clamped to `absoluteExpiresAt` whenever it would exceed it.
4. `revokedAt`/`revokedReason` MUST both be set or both unset.
5. `device.userAgent` and `device.ip` are **informational**. They MUST NOT be used to make an allow/deny decision by the core. They MAY be used for audit signals (e.g. `session.context_changed`).
6. `authMethod`, `amr`, and `authenticatedAt` are written once at creation from the *verified* authentication result and MUST NOT be changed by any later operation.
7. `securityVersionAtIssue` MUST equal the User's `securityVersion` read in the same atomic step that created the session (so a concurrent credential invalidation cannot leave a session with a newer-than-actual version).

## 3. Lifecycle

```
          create
            │
            ▼
        ┌────────┐   touch (extends idle only)    ┌────────┐
        │ active │───────────────────────────────▶│ active │
        └───┬────┘                                └───┬────┘
            │ revoke(reason)                          │ revoke(reason)
            ▼                                         ▼
        ┌─────────┐                              (same)
        │ revoked │   TERMINAL
        └─────────┘
   (expired is derived from time; also TERMINAL: an expired session MUST NOT become active again)
```

1. `revoked` and `expired` are **terminal**. No operation may return a session to `active` ("resurrection"). Re-authentication MUST create a **new** Session with a **new** id.
2. `revoke` MUST be idempotent: revoking an already-revoked session MUST succeed, MUST NOT change `revokedAt`/`revokedReason` (the first reason wins), and MUST NOT emit a duplicate audit event.
3. Revoking a session MUST also cause all refresh tokens of that session to become unusable (see `tokens.md` §3 and `flows/revoke.md`).
4. A session MUST NOT be shared between users, or between devices by the core's own behavior. Re-using one session id for a second login MUST NOT occur (session-fixation prevention; INV-SESS-03).

## 4. Creation

`createSession(user, authResult, device, now)`:

1. MUST be performed only after all authentication checks for the flow have succeeded (`flows/login.md`).
2. MUST always generate a **new** id, regardless of any session or token the caller already presented (INV-SESS-03).
3. MUST enforce the concurrency limit atomically per user (§6).
4. MUST set timestamps from the injected clock.
5. MUST emit audit event `session.created`.

## 5. Touch (sliding idle expiry)

1. When resolving a request (`principal.md` §7.2 step 7), the implementation SHOULD extend `idleExpiresAt` to `min(now + idleTtl, absoluteExpiresAt)` and set `lastSeenAt = now`.
2. To bound write load, touches MAY be throttled: a touch MAY be skipped when `now − lastSeenAt < touchInterval` where `touchInterval` is configurable and MUST be ≤ `idleTtl / 4`.
3. A touch MUST be conditional on the session being non-revoked (a touch on a revoked session MUST NOT modify it and MUST NOT report success).
4. Touch MUST never decrease `idleExpiresAt` and MUST never affect `absoluteExpiresAt`.
5. For access-token transports, refresh (`flows/refresh.md`) is the idle-extension event; a refresh MUST set `idleExpiresAt` per rule 1.

## 6. Concurrency limits

Configuration: `max : Integer ≥ 1 | unlimited`, `onLimit : "evict-oldest" | "reject"`.

1. The count of a user's sessions for limit purposes includes only sessions whose derived status is `active`.
2. The *check-and-create* MUST be atomic per user: when N concurrent logins arrive for a user with limit `max`, then after all complete, the number of `active` sessions MUST be ≤ `max` (INV-SESS-05).
3. `evict-oldest`: when creating a session would exceed `max`, the session(s) with the smallest `createdAt` (ties broken by smallest `id`) MUST be revoked with reason `evicted` as part of the same atomic operation, and the new session created.
4. `reject`: when creating would exceed `max`, creation MUST fail with `SESSION_LIMIT_REACHED` and nothing is modified. No credentials may be issued.
5. `unlimited` MUST be an explicit configuration value; the default `max` MUST be finite (default 10).
6. Evicted sessions' refresh tokens MUST be revoked in the same atomic operation.

## 7. Listing and remote revocation

1. `listSessions(userId)` MUST return only the caller-visible fields: `id`, `createdAt`, `lastSeenAt`, `device`, `authMethod`, and a boolean `current` (computed by comparing with the requesting Principal's `sessionId`). It MUST NOT return any token, token hash, or secret.
2. `listSessions` MUST return only `active` sessions unless explicitly asked for history; revoked/expired sessions MAY be returned only to privileged callers.
3. A caller MUST be authorized to list/revoke sessions of `userId`: a Principal MAY act on its own sessions without any additional permission; acting on another subject's sessions MUST require authorization via the authorization layer (permission `session:revoke` or `session:read`, evaluated through `authorize`, see `rbac/permissions.md` §6).
4. `revokeSession(sessionId)` MUST NOT disclose whether a session id belonging to another user exists (an id not owned by the caller and for which the caller is not authorized MUST yield the same result as an unknown id: `NOT_FOUND`).

## 8. Retention

1. Expired and revoked session records and their refresh-token records SHOULD be retained for at least `max(accessTtl, reuseWindow) + 24 h` after becoming terminal, so that reuse detection and audit remain possible, and MAY be deleted afterwards.
2. Deletion of a *terminal* session MUST NOT make a previously-presented credential valid again (a credential referencing an absent session MUST be treated as `TOKEN_INVALID`; INV-SESS-01).
